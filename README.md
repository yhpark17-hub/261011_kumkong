# 금콩 — 금융공기업 채용 캘린더

금융공기업·공공기관·공제회·중앙회·시중은행 채용 일정(서류 마감·필기·면접·발표)을 한 달력에서 보여주는 웹사이트입니다.

## 실행

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # 프로덕션 빌드
npm run start      # 빌드 결과 실행
```

## 콩밭(익명 게시판) · 필기 후기

- **익명 글쓰기**: 회원가입 없이 닉네임 + 비밀번호(수정·삭제용)로 글·댓글을 씁니다. 닉네임 옆에는 IP 앞 두 자리만 보이고, DB에는 IP 원본 대신 해시만 저장합니다.
- **운영자 글**: `/admin/login`에서 로그인하면 글·댓글에 '운영자' 배지가 붙고, 공지 고정·간단한 서식(## 소제목, **굵게**, - 목록, > 인용, [링크](https://…))을 쓸 수 있습니다. '운영자·관리자·금콩'이 들어간 닉네임은 일반 이용자가 쓸 수 없습니다.
- **필기 후기**: 채용 데이터의 필기 일정에서 시험 목록을 자동으로 만들고(`/reviews/[기관id-날짜]`), 시험일이 지나면 투표가 열립니다. 브라우저당 1회(쿠키) + 같은 IP 최대 3명으로 중복을 막고, 다시 내면 수정됩니다.
  - **응시 확인 + 응시자 우선 공개**: 시험 후 14일 안에 처음 들어오면 "#월 #일 시험에 응시하셨나요?"를 묻습니다. 시험일 포함 3일(`PRIORITY_DAYS`) 동안 상세 결과는 후기를 남긴 사람에게만 보이고(서버에서 잠금), 그 뒤에는 누구나 봅니다. 미응시자는 기다리면 볼 수 있으니 허위로 참여할 이유가 줄고, 응시자는 '미응시'를 누르면 3일을 기다려야 하므로 정직하게 답하는 쪽이 가장 빠릅니다.
  - **못 푼(찍은) 문항 수**: NCS·전공 영역별로 구간(0 / 1~3 / 4~6 / 7~10 / 11~15 / 16+)을 고르게 하고, 아는 사람만 총 문항 수를 적게 합니다. 총 문항 수는 제보 3건 이상 + 절반 이상 일치할 때만 보여 주고, 그때 "약 몇 문항 풀이"도 함께 계산합니다. 회차 이름에 영역이 적혀 있으면(예: "2차 필기 (전공·논술)") 그 영역만 묻고, 논술은 제외합니다.
- **기관 구분 칩**: 기관 비교·필기 후기 목록은 대표 4개 구분(금융공기업·금융유관기관·일반 공공기관·공제회·조합)만 먼저 보여 주고 나머지는 '더보기'로 펼칩니다 (`src/components/CategoryChips.tsx`의 `PRIMARY_CATEGORIES`).
- **제보·의견 보내기**: 기관 상세(사이드 카드·하단 문구)와 기관 패널의 '정보 제보하기', 헤더의 '공고 제보하기', 화면 오른쪽 아래 '의견 보내기'·푸터 링크가 같은 팝업(`src/components/feedback/Feedback.tsx`)을 엽니다. 내용·근거 링크·보낸 화면이 `feedback` 테이블에 쌓이고 `/admin`의 '제보·의견'에서 처리 완료/삭제합니다(처리하면 답변용 이메일은 지워짐). 운영자로 로그인하면 콩밭 상단 띠에 '새 제보 N' 배지가 보입니다.
- **사진·파일 첨부**: 글쓰기에서 사진·PDF·한글·오피스 문서·zip·txt를 파일당 4MB, 최대 10개까지 붙일 수 있습니다. 사진은 올리기 전에 브라우저에서 긴 변 1920px로 줄이고, 서버는 확장자와 파일 앞부분(매직 바이트)이 맞는지 확인합니다. 익명 사용자는 10분에 20개·하루 60MB까지. 저장소는 배포에서 Vercel Blob, 로컬에서 `data/uploads/` (`src/lib/server/storage.ts`). 운영자가 글을 완전 삭제하면 첨부도 지웁니다.
- **콩밭 기관별 보기**: 목록에 '기관' 열이 있고, '기관별 보기'에서 검색해 고르거나 기관 이름을 누르면 그 기관 글만 봅니다 (`/board?company=fss`).
- **도배·신고**: 글 30초·댓글 10초 간격 제한, 금칙어, 링크 2개 제한, 숨은 스팸 함정 칸. 신고 5건이면 자동 숨김 → `/admin`에서 복구·삭제.

### 환경변수 (.env.local)

| 이름 | 설명 |
| --- | --- |
| `DATABASE_URL` | 로컬은 `file:data/kumkong.db`(자동 생성). 배포 시 Turso 주소 `libsql://…` |
| `DATABASE_AUTH_TOKEN` | Turso 토큰 (로컬 파일 DB는 불필요) |
| `ADMIN_PASSWORD` | 운영자 로그인 비밀번호 |
| `ADMIN_SECRET` | 운영자 세션 서명 키 (16자 이상 무작위 문자열) |
| `IP_SALT` | IP 해시용 무작위 문자열 (한 번 정하면 바꾸지 마세요 — 바꾸면 중복 방지 기록이 초기화됨) |
| `BLOB_READ_WRITE_TOKEN` | 첨부·매거진 사진 저장소. Vercel → Storage → Blob 을 프로젝트에 연결하면 자동으로 들어감 (로컬은 불필요) |
| `AUTOMATION_TOKEN` | 자동 점검 에이전트가 `/api/automation/*` 를 부를 때 쓰는 토큰 (24자 이상) |
| `GITHUB_TOKEN` | (선택) 승인한 일정 수정을 바로 커밋할 fine-grained 토큰 — 이 저장소 Contents 읽기·쓰기만 |

로컬 개발용 값은 `.env.local`에 이미 무작위로 만들어 두었습니다. 운영자 비밀번호는 그 파일에서 확인하고, 배포할 때는 새 값으로 바꿔 Vercel 환경변수에 넣으세요.

### 배포 시 DB

Vercel 같은 서버리스 환경은 파일이 유지되지 않으므로 로컬 SQLite 파일 대신 [Turso](https://turso.tech)(SQLite 호환, 무료 플랜 있음)를 씁니다.

```bash
turso db create kumkong
turso db show kumkong --url        # → DATABASE_URL
turso db tokens create kumkong     # → DATABASE_AUTH_TOKEN
```

테이블은 첫 요청 때 자동으로 만들어집니다(`src/lib/server/db.ts`의 SCHEMA).

#### Vercel 배포 순서

1. [Turso](https://turso.tech)에서 DB를 만들고 주소(`libsql://…`)와 토큰을 발급받습니다 (대시보드에서도 가능).
2. 프로젝트 폴더의 `.env.vercel`(gitignore 대상, 운영용 무작위 값이 들어 있음)에 Turso 주소·토큰과 운영자 비밀번호를 채웁니다.
3. Vercel → Project → Settings → Environment Variables에서 `.env.vercel` 내용을 붙여 넣습니다 (Import .env 가능).
4. **환경변수를 바꾼 뒤에는 반드시 Redeploy** 합니다 — 빌드 때 값을 읽는 부분이 있어 재배포해야 반영됩니다.

DB가 없거나 연결에 실패해도 사이트 전체가 멈추지 않습니다. 달력·기관 정보는 그대로 보이고, 콩밭·필기 후기 영역만 '준비하고 있어요' 또는 '다시 시도' 안내로 바뀝니다 (`src/components/db/DbSection.tsx`).

## 매거진 (`/magazine`)

리텐션의 중심 섹션입니다. 위쪽 탭으로 두 섹션이 나뉩니다.

- **데일리 브리핑** (`/magazine`): 하루 한 호, 아침에 나가는 **뉴스레터**(`briefing_issues` 테이블 — 그날 `news` 기사를 날짜로 묶음). 한 호는 머리(마스코트 콩이·Vol·날짜·읽는 시간) → 제목 → 오늘의 흐름(여는 글) → **오늘 꼭 알아야 할 3가지**(헤드라인+핵심 기사의 한 줄 요약) → 오늘의 시간표(목차) → 01 헤드라인(표지·요약·왜 중요할까) → 핵심 기사 → 한 줄로 보는 뉴스 → 오늘의 용어 → 오늘의 면접 질문(답변 뼈대) → 맺는 말·의견 보내기 순서. 기사 사이에는 콩이가 말풍선으로 쉼표를 찍어요. 기사마다 비중(`tier`: 핵심/한 줄)·순서(`position`)·한 줄 요약(`takeaway`). 호별 주소 `/magazine/letter/YYYY-MM-DD`(운영자는 초안 미리보기), **지난 브리핑**(`/magazine/archive`)은 기간으로 지난 레터를 찾고 카테고리를 고르면 기사별로 봅니다. 기사 상세(`/magazine/news/[id]`)는 실린 레터로 이어져요. 운영자는 `/admin/news`에서 레터 초안을 미리보기로 확인하고 '발행'(그날 기사도 함께 공개)을 누릅니다. 사진은 운영자가 직접 올린 파일만(언론사 사진은 저작권 때문에 쓰지 않음).
- **금융 블로그** (`/magazine/blog`): 필기 · 금공 지식 · 입문 가이드 · 꿀팁 · 면접 · 현직자 이야기. 위쪽 주제 칩 하나로 분류하고, 에디터 추천 1편 → 전체 글(최신순/인기순, 카드/목록 보기 — 고른 보기는 기억) → 옆에 많이 읽은 글. 운영자는 `/admin/magazine`에서 씁니다. 합격 수기·웹툰은 숨김(`hidden`) — `src/lib/magazine-meta.ts` 에서 켤 수 있습니다.
- **다시 오게 만드는 장치**: 읽은 글 표시·글 저장(로그인 없이 그 브라우저에만), 읽기 진행 막대, 도움돼요, 공유, 함께 읽을 글, 글 끝의 '이번 주 채용 일정'·'콩밭' 연결, RSS(`/magazine/rss.xml`). 글별 조회수·도움돼요와 방문 통계는 운영자 화면에서 봅니다.
- **본문 서식**: `## 소제목`, `**굵게**`, `==형광펜==`, 목록·체크리스트, `> [!팁] 제목`(팁·주의·요약·포인트·용어·메모 상자), 표, `![설명](사진)`, `출처: [언론사](주소)` — `src/components/magazine/Markdown.tsx` (HTML 을 그대로 넣지 않는 안전한 렌더러)
- **예약 발행**: 공개 시각을 정해 두면 그 시각부터 자동으로 보입니다 (매일 아침 7시 브리핑 등).
- 예전 '필기 가이드'(`/guide`)는 금융 블로그 첫 글로 옮겼고, 주소는 `/magazine`으로 넘어갑니다.

## 홈 · 필기 후기 · 공유 썸네일

- **필기 후기 LIVE**: 오늘 치른 시험은 맨 위 빨간 LIVE 영역에 크게 보이고, 오늘 참여 수·최근 1시간 참여 수·마지막 후기 시각(모두 실제 수치)을 보여 줍니다. 지난 시험은 그 아래.

## 자동 점검 (클라우드 루틴)

Claude 클라우드 루틴이 `scripts/automation/ROUTINE.md` 지침대로 실행됩니다. **사이트를 직접 바꾸지 않고**, 판단을 운영자 화면에 올립니다.

| 루틴 | 한국 시간 | 하는 일 |
| --- | --- | --- |
| 점검 | 매일 06:30 · 12:00 · 20:00 | 승인된 일정 반영 → 새 제보 판단 → 빈 곳 있는 기관 최대 5곳 조사(72시간 안에 본 곳은 건너뜀) → 제안 |
| 브리핑 (아침 레터) | 매일 06:00 | 그날 레터 초안 한 호 — 헤드라인 1·핵심 2 안팎·한 줄 뉴스 3~5 + 오늘의 용어·면접 질문 |

1. `/api/automation/inbox` 에서 새 제보·데이터 빈 곳·최근 점검 기록·사흘 안의 채용 일정·승인된 건을 받아옵니다 (제보의 연락처·IP 는 주지 않음).
2. 제보마다 공식 출처로 사실을 확인하고 처리 방법(일정 반영 / 처리 완료 / 보류 / 삭제)을 제안합니다.
3. 바뀐 일정은 '지금 사이트 vs 제안' 비교와 근거 링크로 제안합니다 (`apply-updates.mjs --preview`). 출처 없는 날짜는 만들지 않습니다.
4. 브리핑 레터는 초안으로만 들어가고, 운영자가 `/admin/news`에서 미리보기로 확인한 뒤 발행합니다 (`/api/automation/issue`).
5. 운영자가 `/admin/proposals`에서 승인하면: `GITHUB_TOKEN`이 있으면 즉시 `recruitment-updates.json`에 커밋 → Vercel 재배포(1~2분), 없으면 다음 점검 때 루틴이 커밋합니다.

루틴 환경(claude.ai → 루틴 → 환경 설정)에는 `KUMKONG_SITE_URL`(사이트 주소)과 `AUTOMATION_TOKEN`을 넣고, 네트워크 접근은 기관 사이트·뉴스를 조사할 수 있게 **Full** 로 둡니다(기본 허용 목록은 `*.vercel.app`을 막습니다).

## 데이터 업데이트

일정은 `src/data/recruitments.ts`, 기관 정보는 `src/data/companies.ts`에서 수정합니다.

- `status: "confirmed"` — 올해 공고로 확인된 일정 (달력에 실선 칩)
- `status: "expected"` — 공고 전 전년도 기준 예상 일정 (달력에 점선 칩, '예상' 표시)
- 날짜는 `YYYY-MM-DD`(한국 시간), 기간은 `endDate`, 마감 시각은 `time: "18:00"`
- 모르는 값은 지어내지 말고 비워 두세요. 화면에 "확인 중"으로 표시됩니다.
- 같은 단계가 여러 회차면 `label`로 구분합니다 (예: `"1차 면접 ① 집단토론"`).
- `sourceUrl`·`confidence`(high = 공고문 원문 대조)를 넣으면 화면에 출처와 검증 수준이 표시됩니다.

### 리서치 결과 일괄 반영

직접 정리한 기관(`src/data/*.ts`) 외의 기관은 리서치 JSON을 병합해 `src/data/generated/*.json`으로 만듭니다.

```bash
node scripts/merge-research.mjs research1.json research2.json --report report.txt
```

날짜 형식, 전형 순서 역전, 라벨 없는 중복 단계, 경쟁률(지원자÷채용) 불일치를 자동 검사하고 확인할 항목을 리포트로 남깁니다.

### 최신 일정 업데이트 (기관 일부만)

필기 날짜 추가, 새 하반기 공고 반영처럼 일부 기관만 고칠 때는 업데이트 파일을 씁니다.

```bash
node scripts/apply-updates.mjs updates1.json updates2.json --report report.txt
```

입력은 `[{ id, found, isNewCycle, recruitment: { title, period, events, tracks, ... }, verification: { primarySource, confidence }, changes }]` 형식이고, 결과는 `src/data/generated/recruitment-updates.json`에 쌓입니다. 화면에는 이 파일이 직접 정리한 데이터·리서치 데이터보다 우선합니다. 일정은 새로 확인한 목록으로 바뀌고, 직렬·인원·자소서 문항은 새 값이 없으면 기존 값을 유지합니다. 기존 일정이 빠지거나 출처가 충돌하면 리포트에 남습니다.

### 로고

```bash
node --use-system-ca scripts/fetch-logos.mjs            # 로고 없는 기관만
node --use-system-ca scripts/fetch-logos.mjs --only lh,ex
node scripts/promote-wide-logos.mjs                     # 정사각형에 가까운 가로형 로고를 아바타로도 사용
```

공식 홈페이지 아이콘과 `scripts/logo-sources.json`(기관 공식 CI 페이지의 심볼 이미지 URL·잘라낼 영역)을 바탕으로 `public/logos/`에 128px PNG를 만듭니다. 로고는 각 기관의 상표이며 기관 식별 목적으로만 표시합니다. 정식 서비스 전에는 기관별 CI 사용 지침을 확인하세요.
